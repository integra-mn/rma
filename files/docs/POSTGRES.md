# PostgreSQL

The app runs on **PostgreSQL** (production target) and still runs on MySQL.
Which one is used is decided by a single setting: `DB_DRIVER`.

```
DB_DRIVER=pgsql      # or: mysql
DB_HOST=127.0.0.1
DB_PORT=5432         # 3306 for mysql
DB_NAME=integra_rma
DB_USER=integra
DB_PASS=…
```

## How the port works

Queries throughout the app stay written in one dialect (MySQL-flavoured).
Three pieces bridge the gap:

| Piece | File | Job |
|---|---|---|
| DSN + `RETURNING id` | `config/db.php` | Connects to either engine; Postgres has no `lastInsertId()`, so inserts use `RETURNING id`. |
| SQL translator | `config/db.php` → `db_translate()` | Rewrites the five MySQL-only constructs still in use: `LIKE`→`ILIKE`, `DATE_FORMAT`→`to_char`, `DATEDIFF`, `DATE_ADD/SUB … INTERVAL`, `YEAR()/MONTH()`→`EXTRACT`. Cached per query string. |
| Schema generator | `tools/mysql2pg.py` | Turns `schema.sql` (MySQL, the source of truth) into `schema.pgsql.sql`. |

Anything that could be written portably **was** — `IFNULL`→`COALESCE`,
`CURDATE()`→`CURRENT_DATE`, `SUM(bool)`→`SUM(CASE WHEN … THEN 1 ELSE 0 END)`,
and `GROUP BY` clauses list every selected joined column. Those all run
unchanged on both engines, so the translator stays small.

### Type mapping

| MySQL | Postgres | Why |
|---|---|---|
| `INT UNSIGNED AUTO_INCREMENT` | `INTEGER GENERATED BY DEFAULT AS IDENTITY` | "BY DEFAULT" lets a migration supply explicit ids |
| `INT/SMALLINT UNSIGNED` | `INTEGER` | Postgres has no unsigned types |
| `TINYINT(1)` | `SMALLINT` | **not** `BOOLEAN` — the app compares `= 1` |
| `DATETIME` | `TIMESTAMP` | |
| `ENUM(...)` | `VARCHAR` + `CHECK (col IN ...)` | same integrity, standard SQL |
| `SET(...)` | `VARCHAR` | app stores a comma-joined list |
| `JSON` | `JSONB` | every write goes through `json_encode()` |
| `ON UPDATE NOW()` | `touch_updated_at()` trigger | Postgres has no column-level equivalent |
| inline `INDEX` | separate `CREATE INDEX` | |

## Deploying to the Proxmox container

```bash
# 1. Postgres
apt install postgresql
sudo -u postgres createuser --pwprompt integra
sudo -u postgres createdb -O integra integra_rma

# 2. Schema (regenerate first if schema.sql changed)
python3 tools/mysql2pg.py
psql -U integra -d integra_rma -f schema.pgsql.sql

# 3. Point the app at it — files/.env
DB_DRIVER=pgsql
DB_PORT=5432

# 4. PHP extensions (pgsql for the DB, gd for QR codes, fileinfo for spreadsheets)
apt install php-pgsql php-gd php-fileinfo && systemctl restart php*-fpm

# 5. Composer dependencies
composer install --no-dev
```

### Moving existing MySQL data across

`tools/mysql2pg_data.php` copies every table, then resets the identity
sequences so new inserts continue from the right number.

```bash
php tools/mysql2pg_data.php          # dry run — prints row counts
php tools/mysql2pg_data.php --run    # do it
```

MySQL connection details come from `MY_HOST / MY_PORT / MY_NAME / MY_USER /
MY_PASS` (so the app's own `.env` can already point at Postgres); the Postgres
side is read from `.env`. It empties the target tables in one statement before
loading — truncating them one-by-one with `CASCADE` would delete rows already
copied.

## Local development

Local dev runs Postgres so it matches production.

```bash
tools/pg_reload.sh                   # rebuild the local DB from schema.sql
php tools/mysql2pg_data.php --run    # optional: pull the MySQL dev data across
```

To go back to MySQL locally, restore `.env.local.mysql-backup` over `.env.local`.

## Gotchas

- **`LIKE` is case-sensitive in Postgres.** The translator turns every `LIKE`
  into `ILIKE`, which is what MySQL's default collation did. Don't "fix" a
  search by hand-writing `ILIKE` — leave `LIKE` and let the translator do it.
- **`GROUP BY` is strict.** Postgres only infers a functional dependency from
  the grouped table's own primary key. Any column selected from a *joined*
  table must be listed in `GROUP BY`.
- **No implicit boolean→int.** `SUM(x = 0)` fails; use
  `SUM(CASE WHEN x = 0 THEN 1 ELSE 0 END)`.
- **Placeholders need a type** in arithmetic — the translator casts them
  (`(?)::timestamp`, `(?)::int`) inside interval maths.
- Regenerate `schema.pgsql.sql` after **any** change to `schema.sql`; it is a
  build artefact, not something to edit by hand.
